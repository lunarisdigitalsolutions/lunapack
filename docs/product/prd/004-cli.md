# CLI

## Purpose

The `luna` CLI is the consumer-project interface for adopting and maintaining LunaPack packs.

## Distribution

Luna releases support Windows x64, Linux x64, Linux Arm64, macOS x64, and macOS
Arm64. Consumers can install a release archive, the npm package
`@lunarisdigitalsolutions/lunapack`, or the `Lunaris.Lunapack.Luna` .NET tool.

## Project And Sources

- `init`: Create portable configuration and empty resolved state.
- `sources add local`: Register a relative local pack source.
- `sources add git`: Register a Git pack source.
- `sources add github`: Register a GitHub repository through its owner/name.
- `sources list`: List configured pack sources.
- `sources remove`: Remove source configuration and bound project trust while
  retaining installed-pack evidence.
- `trust`: Grant, list, and revoke lifecycle-script trust by scope.
- `variables`: Manage reusable project parameter values.
- `remap`: Manage portable target remappings.

## Catalog

- `discover`: List the latest pack release for each ID.
- `search`: Group matching packages and display up to three latest releases by
  default. `--versions` selects a positive count.
- `validate`: Validate one pack release and its selected files.
- `inspect`: Show resolved pack metadata, parameters, dependencies, and targets.

## Lifecycle And Audit

- `install`: Resolve and materialize a requested root pack graph.
- `uninstall`: Remove a root and only its unreachable managed content.
- `outdated`: List roots with a newer available release.
- `update`: Apply an available release to all or one installed root.
- `mv`: Relocate one managed file while retaining lock ownership.
- `audit`: Report resolved packs, source locations, dependencies, and ownership.

## Safety Principles

Commands validate before mutation, recover copied or removed targets when
state persistence fails, and never bypass source or lifecycle policy.

Install accepts typed parameters and compatible project variables. Update and
install support dry runs; update-all can request confirmation per available
root. Invalid input, resolution, planning, or write behavior must leave project
state safe.

## Contextual Guidance

An empty `luna` invocation summarizes workspace maturity and recommends the next
core action. Successful setup, catalog, install, update, and uninstall commands
provide at most three ordered follow-up commands. Missing workspace, missing
source, and unresolved-pack failures include one short recovery block without
changing the failure result.
